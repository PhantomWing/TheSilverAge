# The Silver Age - Minecraft Mod

A vanilla-friendly NeoForge mod for Minecraft 1.21.1 that adds oxidizable silver content.

## Tech Stack

- **Minecraft** 1.21.1 / **NeoForge** 21.1.218
- **Java** 21
- **Build**: Gradle with NeoForge ModDev plugin v1.0.14
- **Mappings**: Parchment 2024.07.28
- **Mod ID**: `thesilverage`
- **Package**: `com.phantomwing.thesilverage`

## Build & Run Commands

```bash
./gradlew build              # Build the mod
./gradlew runData            # Run data generation (outputs to src/generated/resources/)
./gradlew runClient          # Launch Minecraft client with mod
./gradlew runServer          # Launch dedicated server with mod
./gradlew runGameTestServer  # Run game tests
```

## Key Conventions

### Registration Pattern

All registries use NeoForge `DeferredRegister` with static fields:

```java
public class ModBlocks {
    public static final DeferredRegister.Blocks BLOCKS = DeferredRegister.createBlocks(MOD_ID);
    public static final DeferredBlock<Block> EXAMPLE = BLOCKS.register(...);
    public static void register(IEventBus eventBus) { BLOCKS.register(eventBus); }
}
```

Registration classes are wired in `TheSilverAge.registerManagers(IEventBus)`.

### Naming Conventions

- Registry classes: `Mod{Type}s.java` (ModBlocks, ModItems, ModTiers, etc.)
- Datagen providers: `Mod{Type}Provider.java` (ModRecipeProvider, etc.)
- Tags: `ModTags` for mod-namespaced, `CommonTags` for `c:` namespace
- Constants reference: `TheSilverAge.MOD_ID`

### Weathering/Oxidation Pattern

Silver blocks follow the copper oxidation pattern with four states: UNAFFECTED -> EXPOSED -> WEATHERED -> OXIDIZED. Each state has a normal and waxed variant. Registration uses generic helper methods in ModBlocks (e.g., `registerWeatheringSilverBlock()`). Mappings are defined in `ModOxidizables` and `ModWaxables`.

### Data Generation

- Providers are registered in `DataGenerators.java` (uses `@EventBusSubscriber`)
- Output goes to `src/generated/resources/` - these files are recreated every run
- Conditional recipes/loot use `ConfigBooleanCondition` wrapping config values
- Block tags provider must run before item tags provider (dependency)

### Config System

`Configuration.java` defines boolean options via `ModConfigSpec`:
- `SILVERFISH_DROP_SILVER`, `OVERRIDE_VANILLA_RECIPES`, `GENERATE_STRUCTURE_LOOT`
- `ENABLE_VILLAGER_TRADES`, `ENABLE_WANDERING_TRADER_TRADES`
- Accessed at runtime via `Configuration.getBooleanConfigurationValue(String id)`
- Used in datagen conditions via `ConfigBooleanCondition`

### Creative Tab

`ModItems.CREATIVE_TAB_ITEMS` (LinkedHashSet) tracks insertion order for the creative tab. Items are auto-added during registration via helper methods.

## Dependencies (runtime only)

- JEI, AppleSkin, Jade - loaded at runtime for dev testing, not compiled against
